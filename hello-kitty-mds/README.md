# 포트폴리오 — Unity 모바일 게임 라이브 이벤트 컨텐츠

머지(Merge) 장르 모바일 게임의 **라이브 이벤트 컨텐츠 5종** 클라이언트 구현 코드입니다.
운영 중인 상용 프로젝트에서 발췌했으며, 각 컨텐츠는 기획 명세 → 설계 → 구현 → 라이브 대응까지 거친 실제 코드입니다.

## 컨텐츠별 한 줄 소개

- **트로피 챌린지** — 여러 라이브 이벤트의 플레이를 하나의 시즌 도전과제로 묶어 최종 보상을 주는 메타 레이어. 인터페이스 기반 계층 분리(Repository / StateEvaluator / SortPolicy)가 특징.
- **드림 벌룬 페스티벌** — 난이도를 골라 참가하고, 줄어드는 좌석을 두고 AI와 경쟁하는 이벤트. **결정론적 시간 함수 기반 시뮬레이션**으로 오프라인 진행을 재현.
- **당근 수확 대소동** — 20초 동안 구멍에서 튀어나오는 당근을 터치하는 아케이드 게임. 순수 C# 모델(스폰 추첨 / 점수·콤보 / 보드 상태)과 Unity 뷰를 완전히 분리.
- **생일 카페 풍선 게임** — 카페 오브젝트에서 진입하는 그리드 풍선 터뜨리기 미니게임. 서브 컨텐츠 인터페이스로 메인 컨텐츠에 합성.
- **4 Drop Item** — 머지판에 블록을 소환해 도감을 채우는 이벤트. 확률 주기(천장) 로직과 다단계 연출 시퀀스를 포함.

## 이 코드에서 봐주셨으면 하는 부분

### 1. 주석이 "왜"를 남긴다

이 코드베이스는 의도적으로 주석 밀도가 높습니다. 코드를 반복하는 주석이 아니라 **판단 근거**를 남깁니다.

```csharp
// 단계 수치를 상수로 박지 않는 이유: 기획서가 "N단계"의 N을 두 절에서 서로 다르게 적어 모순 상태다.
// 그래서 "더 이상 업그레이드가 없는 최종 단계인가"로만 판정한다(수치가 바뀌어도 CSV 행 수만 바뀐다).
// 최종 단계 규약은 CSV 실측으로 확인했다 — MergeEvent_Block_Main.csv 의 upBlockIdx 는 자기참조가 아니라
// '없음 = 0' 규약이고(dangling 참조 0건), 그룹 내 최고 blockLevel 행이 0을 갖는다.
```
— `05_FourDropItem/Helper/MergeEventFourDropItemHelper.cs`

기획 문서의 모순, 뒤집힌 스펙, 반증된 가설과 그 근거까지 코드에 남아 있습니다.
라이브 서비스에서 스펙이 계속 흔들릴 때 **무엇을 믿고 짰는지**를 추적 가능하게 만드는 방식입니다.

### 2. 순수 로직과 Unity 의존을 분리한다

당근뽑기의 `EventCarrotScoreModel` / `EventCarrotSpawnSelector` / `EventCarrotBoardModel` 은
`UnityEngine.Random` 외에 엔진 의존이 없습니다. 트로피 챌린지의 `TrophyChallengeStateEvaluator` 는
`static` 순수 함수 집합입니다. 테스트 가능성과 재사용성을 위한 의도적 경계입니다.

### 3. 서버 권위와 클라 시뮬을 명시적으로 나눈다

드림 벌룬은 **진행 상태는 서버 권위**, **좌석 감소·순위·성공 판정은 클라 시뮬**로 축을 나눴습니다.
그 경계가 코드와 주석에 분명히 적혀 있고, 시뮬은 "시간의 결정론적 함수"로 설계해
재접속·백그라운드 복귀에도 같은 결과가 나오도록 했습니다.

### 4. 테이블(CSV) 스펙 변화를 흡수한다

수치를 코드에 박지 않고 CSV를 단일 진실로 두되, **미발행·미매칭 시 폴백**을 명시합니다.
기획 발행이 늦어져도 컨텐츠가 죽지 않게 하는 처리가 곳곳에 있습니다.

## 참고 — 코드 기여도에 관하여

이 저장소는 글로벌 브랜치를 중국 브랜치로 **스쿼시 머지**하는 구조라, git 커밋 저자만으로는
원 작성자를 판별할 수 없습니다. 대부분의 파일이 `Merge origin/release/... into china/merge/...`
단일 커밋으로 유입되어 있습니다.

각 컨텐츠 README 하단에 **git 이력상 확인 가능한 기여 범위**를 사실대로 적어두었습니다.
포트폴리오로 제출하실 때는 그 항목을 확인하시고, 본인 기여가 명확한 부분 위주로 설명하시길 권합니다.

git 이력상 **`05-four-drop-item` 은 전 파일이 단일 작성자 커밋으로만 구성**되어 기여가 가장 명확합니다.
