# 02. 드림 벌룬 페스티벌 (Dream Balloon Festival)

> 난이도 선택 · AI 경쟁 · 좌석 쟁탈 구조의 라이브 이벤트

---

## 컨텐츠 개요

플레이어는 **난이도(쉬움 / 보통 / 어려움)** 를 골라 축제에 참가합니다.
각 라운드에는 정해진 수의 **좌석**이 있고, AI 참가자들이 시간이 지날수록 좌석을 채워갑니다.
좌석이 0이 되기 전에 목표 코인을 모으면 성공, 못 모으면 실패입니다.

```
난이도 선택 → 라운드 시작 → [머지 플레이로 코인 획득]  vs  [시간에 따라 좌석 감소]
                                       │                          │
                              목표 코인 달성 → 성공          좌석 0 도달 → 실패
                                       │
                              다음 라운드 or 쉬어가기 → ... → 최종 보상
```

이벤트 상태는 서버가 관리합니다 — `0 미시작 / 1 쉬어가기 / 2 진행중 / 3 클리어 / 4 종료`.
라운드 사이에는 "쉬는 중" 구간이 있어 플레이어가 재출발을 선택합니다.

---

## 아키텍처 — 서버 권위와 클라 시뮬의 경계

이 컨텐츠의 핵심 설계 판단은 **무엇을 서버가 갖고 무엇을 클라가 계산하는가** 였습니다.

```
┌──────────────────── 서버 권위 ────────────────────┐
│  EventBalloonInfo — 이벤트 상태 / 라운드 / 난이도  │
│  코인 누적 / 보상 지급 / 라운드 클리어 확정        │
└───────────────────────┬───────────────────────────┘
                        │ SyncFromServer
                        ▼
        ┌──────────────────────────────┐
        │  ContentEventDreamBalloon    │  오케스트레이션
        │  Request* → 서버 요청         │
        │  Message  → UI 상태 전파      │
        └───────┬──────────────┬───────┘
                │              │
                ▼              ▼
  ┌────────────────────┐  ┌──────────────────────┐
  │ SeatSimulator      │  │ RestNotifier         │
  │ 좌석 감소 · 순위   │  │ 쉬는중 안내 발화 조건 │
  │ 성공/실패 판정     │  │ UniTask 조건 루프    │
  │ (시간의 결정론 함수)│  └──────────────────────┘
  └────────────────────┘
```

**좌석은 왜 서버가 아니라 클라인가** — 좌석 감소는 초 단위로 계속 일어나는 연출성 수치입니다.
매번 서버가 내려주면 통신량이 폭증합니다. 대신 **시간의 결정론적 함수**로 만들어
서버는 `roundStartAt` 하나만 주고 클라가 언제 계산해도 같은 값이 나오게 했습니다.

```csharp
/// - 좌석 수를 **서버 roundStartAt 이후 경과 시간의 결정론적 함수**로 관리한다. Event_DreamBalloon_AiRound 의
///   decayMinSec~decayMaxSec 간격 수열을 라운드별 시드(eventSeq·round)로 재현하므로, 언제 계산해도(재접속·백그라운드
///   복귀 포함) 같은 시점엔 같은 좌석 수가 나온다 → 앱을 닫아도 좌석은 계속 줄고, 재접속 시 위상 어긋남이 없다.
```

앱을 껐다 켜도, 백그라운드에 있다 돌아와도 좌석 수가 튀지 않습니다.
UniTask 루프는 좌석 수를 *만드는* 게 아니라 **다음 감소 경계까지 대기했다가 UI에 통지만** 합니다.

## 기술적으로 볼 만한 부분

### 1. 결정론적 시뮬레이션

좌석 감소 간격은 `Event_DreamBalloon_AiRound` 의 `decayMinSec ~ decayMaxSec` 범위 난수입니다.
그냥 난수를 쓰면 재접속마다 다른 값이 나오므로, **라운드별 시드(`eventSeq`·`round`)** 로
같은 수열을 재현합니다. 좌석 수는 "지금까지 몇 번의 감소 경계를 지났는가"의 함수입니다.

부수 효과로 다음이 함께 해결됩니다.

- 오프라인 진행 (앱을 꺼도 좌석은 줄어 있음)
- 백그라운드 복귀 시 위상 보정 불필요
- 서버-클라 좌석 동기화 통신 불필요

### 2. 판정과 연출의 분리

성공/실패 **판정**은 시뮬레이터가 갖고, 연출은 순수 view 입니다.
그래서 연출을 스킵해도 데이터가 깨지지 않습니다 — 강제 종료에도 안전하고,
서버 커밋 후 재생해도 됩니다.

```csharp
/// - 성공/실패 "판정"은 이 Helper 가 보유한다. 목표 코인 달성 시 OnGoalReached 로 성공 확정 →
///   이후 좌석 감소 중단(감소 정지). 좌석 0 도달 = 실패.
/// - 순위 = slotMax - 잔여좌석 + 1 (좌석 점유 순서), 모집단·상위% 분모 = 라운드별 slotMax.
/// - 연출은 순수 view 이므로, 이 시뮬은 데이터만 산출한다.
```

### 3. 난이도 인코딩 — 변환 0회 계약

난이도 값은 **프리팹 인스펙터 → UI → 패킷 → 서버** 까지 변환 없이 그대로 흘러갑니다.

```csharp
// 난이도 인코딩 — 패킷·테이블·프리팹이 같은 값을 쓴다(서버·클라 통일 확정).
//  변환 지점이 하나도 없는 것이 계약이다 — 프리팹 인스펙터에 박힌 int 가 RQEventBalloonStart 까지 그대로 간다.
public const int DIFFICULTY_EASY = 1;
public const int DIFFICULTY_NORMAL = 0;
public const int DIFFICULTY_HARD = 2;
public const int DIFFICULTY_UNSPECIFIED = -1;
```

`enum` 이 아니라 `const int` 인 이유도 명시돼 있습니다 —
① `[SerializeField] int` 로 프리팹에 직렬화되고 ② 테이블 조회 딕셔너리 키이며 ③ 패킷 필드가 `int` 입니다.

**미지정(`-1`) 처리가 이 파일의 핵심입니다.** 미지정 값으로는 난이도 테이블을 조회하지 않습니다.
조회 진입점 4곳(`GetAiRounds` / `GetAiRound` / `GetRewardRow` / `GetRewardGroup`)에 가드를 두었는데,
이유가 두 가지입니다.

1. 테이블 조회 실패가 `DLogger.Error` 를 남겨 **거짓 알람**이 됨
2. `GetRewardRow` 의 레거시 폴백이 **난이도를 보지 않아**, 미지정이 흘러가면
   "데이터 없음"이 아니라 **엉뚱한 난이도의 보상 행**이 정상 값처럼 반환됨

②번이 특히 위험합니다. 가드가 없으면 조용히 틀린 값이 나옵니다.

### 4. 복합 조건 발화기

`DreamBalloonRestNotifier` 는 "쉬는 중" 안내를 언제 띄울지 판단합니다.

```
전제: 쉬어가기로 쉬는중 진입(state == 1)
조건1: 진입 후 지정 시간 경과 AND 남은 에너지 >= 임계값
조건2: 누적 사용 에너지 >= 임계값 (발화 시 0으로 리셋)
        둘 중 하나(OR)
재노출: 쿨다운마다, 라운드당 최대 N회
```

주목할 점은 **발화 실패 시 카운트를 소진하지 않는다**는 것입니다.
안내창이 머지판 전용 UI라 다른 화면에서는 조용히 버려지는데,
그 경우 재노출 잠금과 횟수를 그대로 두고 다음 주기에 재시도합니다.

시간 체크는 컨텐츠 `Update` 폴링이 아니라 **UniTask 루프 + CancellationToken** 으로 처리해
로비/머지 상주 중에도 안전하게 구동·취소됩니다.

### 5. 서버 미구현 구간에 대한 타임아웃 방어

```csharp
private const int FINAL_CLAIM_ROUND = 0;             // 최종 보상의 claim round — 패킷 정의상 0
private const float FINAL_CLAIM_TIMEOUT_SEC = 5f;    // 최종 보상 RS 대기 상한 — 무응답(서버 미구현) 시 연출이 막히지 않게 한다
```

서버 응답이 오지 않아도 연출이 영구 정지하지 않도록 상한을 걸었습니다.
서버 기능이 뒤따라오는 개발 상황을 전제한 방어입니다.
